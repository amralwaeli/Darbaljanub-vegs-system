# The native Android app

The staff app is a real Android app built with [Capacitor](https://capacitorjs.com).
The website and the app are **the same code** in `src/` — there is no second
codebase to keep in sync.

---

## 1. Why this replaced the old TWA

The app used to be a **TWA** (Trusted Web Activity) generated by Bubblewrap: a
Chrome tab wearing an app icon. Nearly every complaint traced back to that one
fact.

| Symptom | Cause in the TWA | Fixed by |
|---|---|---|
| Notifications never arrived | Web Push is delivered to **Chrome**, and OEM battery managers (Xiaomi, Oppo, Huawei, Samsung) kill Chrome's background process | Native **FCM**, delivered by Play Services straight to the app |
| Delivery photos failed | `<input type="file" capture>` returns **HEIC** on many phones; Chrome cannot decode it, so the upload threw | Native **camera**, which returns a ready-to-upload JPEG |
| Random logouts, lost checklist ticks | Session lived in `localStorage`, which Android **evicts** under storage pressure | Native **Preferences** storage, which the OS does not evict |
| "Feels like a browser" | Custom-tab chrome, browser back-button, network-dependent cold start | Native shell: own status bar, real back button, assets loaded from disk |
| WhatsApp orders opened a browser page | `window.open` is unreliable in a WebView | Native **AppLauncher** Intent |

## 2. The update model — read this one

**Staff install the APK once.** After that, code changes reach their phones by
themselves.

```
you push to main
   -> GitHub Actions builds the app twice
        - website  (base /<repo>/)  -> published as the site
        - OTA bundle (base /)       -> published to /<repo>/ota/
   -> every phone checks ota/latest.json on launch and on resume
   -> a newer bundle downloads in the background
   -> it takes effect the next time the app is opened
```

| What you change | What staff must do |
|---|---|
| Screens, Arabic text, prices, business rules, bug fixes, styling, new pages | **Nothing.** Auto-updates. |
| SQL migrations, Supabase functions | **Nothing.** Server-side. |
| A new Capacitor **plugin**, a new permission, the app icon or name, a Capacitor upgrade | Install a new APK (rare) |

Updates are staged with `next()`, never applied mid-session — a driver halfway
through logging a delivery is never interrupted.

**Safety net:** if a published bundle is broken enough that the app fails to
start, the updater rolls back to the last working bundle on its own
(`appReadyTimeout` in `capacitor.config.ts`). A bad deploy cannot brick the
phones.

## 3. One-time setup

### 3a. Firebase (for notifications)

Firebase is **only** the delivery pipe for Android notifications. Supabase
remains the database and the sender. No app data goes to Firebase, and Cloud
Messaging is free with no message quota.

1. Go to <https://console.firebase.google.com> → **Add project**.
   Name it anything (e.g. `darbaljanub-vegs`). **Disable** Google Analytics.
2. In the project, click the **Android** icon to add an app.
   - **Package name:** `com.darbaljanub.vegs` — must match exactly.
   - Nickname and SHA-1 can be left blank.
3. Download **`google-services.json`** and put it at:
   ```
   android/app/google-services.json
   ```
4. **Project settings** (gear) → **Service accounts** → **Generate new private
   key**. This downloads a second JSON file.

   > **The two Firebase files are not interchangeable.** Open each and check:
   > | First lines contain | It is | It goes |
   > |---|---|---|
   > | `"type": "service_account"` | service account key | Supabase (step 5) |
   > | `"project_info"` / `"client"` | `google-services.json` | `android/app/` (step 3) |

5. Give the **service account** JSON to Supabase as a secret. Easiest via the
   dashboard: **Edge Functions → Secrets → Add or replace secrets**
   - **Name:** `FCM_SERVICE_ACCOUNT`
   - **Value:** paste the entire file contents, braces included (the field
     accepts multi-line JSON)

   The escaped `\n` sequences inside `private_key` are expected and handled.

   Or from the CLI:
   ```bash
   npx supabase secrets set FCM_SERVICE_ACCOUNT="$(cat path/to/service-account.json)"
   ```

6. **Deploy the updated function.** Setting the secret is not enough on its own
   — the currently deployed `send-push` is the older, web-push-only version,
   and the FCM code has to be pushed up:
   ```bash
   npx supabase functions deploy send-push --no-verify-jwt
   ```

Web Push for the website keeps working alongside this — the two transports are
independent.

### 3b. Signing key

The APK **must** keep being signed with the same key as the old TWA, or phones
refuse to install it as an upgrade and every device needs a manual uninstall.

```bash
cp android/keystore.properties.example android/keystore.properties
# then fill in the password from twa/keystore-password.txt
```

`android/keystore.properties` is gitignored. Never commit it.

> Keep `twa/android.keystore` backed up somewhere safe. If it is lost, no future
> APK can ever update the installed app.

### 3c. Database migration

Apply `supabase/migrations/0018_native_push.sql`, which adds the `platform`
column that lets `send-push` tell a browser endpoint from an FCM token.

## 4. Building the APK

```bash
npm run android:apk
```

This builds the web bundle with the correct base path, syncs it into the native
project, and assembles a signed release APK at:

```
android/app/build/outputs/apk/release/app-release.apk
```

Send that file to staff. They install it once, over the existing app.

**Minimum Android version: 7.0 (API 24).** The old TWA allowed 5.0. Anyone on
Android 5.x or 6.x cannot install this APK — they are not stranded, because the
old app still points at the website, which keeps auto-updating; they simply keep
the browser-based experience until the phone is replaced.

**JDK note:** Gradle cannot use JDK 22+. The script auto-detects a JDK 17–21
(Android Studio ships one); set `CAPACITOR_JAVA_HOME` to override.

### Other commands

| Command | What it does |
|---|---|
| `npm run dev` | Web dev server, unchanged |
| `npm run build` | Website build (needs `BASE_PATH` for GitHub Pages) |
| `npm run build:native` | Same app built with base `/` for the APK and OTA |
| `npm run sync` | Build native bundle + copy it into `android/` |
| `npm run ota:bundle` | Package `dist/` as an OTA bundle (CI does this) |
| `npm run android:open` | Open the project in Android Studio |

## 5. How the code is organised

Everything platform-specific lives in [`src/lib/native/`](../src/lib/native/).
Feature code never branches on the platform itself.

| File | Responsibility |
|---|---|
| `index.ts` | `isNative` flag + safe wrapper for native side effects |
| `storage.ts` | Supabase session in native storage (no more evictions) |
| `camera.ts` | OS camera returning an upload-ready JPEG |
| `push.ts` | FCM registration, token rotation, notification taps |
| `updater.ts` | OTA check / download / stage |
| `shell.ts` | Status bar, back button, splash, connectivity |
| `links.ts` | Opening WhatsApp via a real Android Intent |

The Capacitor plugins are loaded with **dynamic `import()`** inside
`isNative` branches, so none of them end up in the website's bundle and the web
behaviour is untouched.

## 6. Troubleshooting

**The app never updates.**
Check `https://<user>.github.io/<repo>/ota/latest.json` loads in a browser. Then
confirm that host is allowed by `connect-src` in the CSP in `index.html` — if it
is not, the update check is blocked and fails silently.

**Notifications don't arrive.**
1. `android/app/google-services.json` present at build time?
2. `FCM_SERVICE_ACCOUNT` set, and `send-push` redeployed after setting it?
3. Notification permission granted on the phone (Android 13+ asks)?
4. Check the row in `push_subscriptions` has `platform = 'android'`.

**"App not installed" when installing the APK.**
The APK was signed with a different key than the installed app. Check
`android/keystore.properties` points at `twa/android.keystore` with alias
`android`.

**Blank green screen in the app.**
The bundle was built with the website's base path. Use `npm run build:native`
(or `npm run android:apk`, which does it for you), never `npm run build`.
